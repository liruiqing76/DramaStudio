## 2. 环境准备与启动

### 2.1 系统要求

| 依赖 | 版本 |
|------|------|
| Node.js | >= 18 |
| npm | 随 Node.js |
| 内存 | >= 8GB（推荐 16GB） |
| 硬盘 | >= 10GB 可用空间 |

### 2.2 启动后端（第一次使用）

```bash
cd backend-node

# 1. 安装依赖
npm install

# 2. 复制配置（Windows）
# config.yaml 已随仓库提供，直接编辑即可

# 3. 编辑 config.yaml，填入 AI API Key
#    （也可启动后在网页「AI 配置」页管理）

# 4. 初始化数据库（会自动建表 + 补列，覆盖 8 周所有新表）
npm run migrate

# 5. 启动后端（默认端口 5679）
npm start
```

启动成功后终端输出：
```
Server is ready!
API:       http://localhost:5679/api/v1
```

### 2.3 启动前端（开发模式）

```bash
cd frontweb
npm install
npm run dev
```

浏览器访问 `http://localhost:3013`（自动代理 `/api` 到后端 5679）。

> 💡 也可以不单独启动前端：后端在 `frontweb/dist` 存在时会直接托管成品页面于 `http://localhost:5679`。

### 2.4 必须配置的 AI Key

进入网页右上角 **「AI 配置」**，分三个 Tab 配置：

| 类型 | 必填 | 用途 |
|------|------|------|
| 文本生成 | ✅ 必填 | 剧本/分镜/锚点/模板生故事/评分 |
| 图片生成 | ✅ 必填 | 角色/场景/分镜图 |
| 视频生成 | ✅ 必填 | 分镜视频片段 |
| TTS | 选填 | 音色试听 / 配音（Week 6-7） |

## 3. Week 1 — 角色衣橱系统

### 3.1 概念说明

三层协同解决"同角色长相/服装不一致"问题：

```
L1 多视图   正面/侧面/背面 三视图并行生成
L2 衣橱     同角色多套造型（日常装/战斗装等）可切换
L3 锚点     结构化特征（发型/脸型/体型/肤色/配饰）→ 自动注入 prompt
```

**数据模型**：每个角色下可建多个 `character_outfits`（造型），每个造型可填写锚点字段并生成三视图。

### 3.2 操作流程

#### 步骤 1：为角色创建造型

1. 进入角色的「衣橱」页（角色详情 Tab）
2. 点击 **「添加造型」**
3. 填写：
   - **名称**（必填）：如 "日常装" / "战斗装"
   - **描述**：造型说明
4. 保存

#### 步骤 2：填写特征锚点

在造型中可手动填写，或一键 AI 提取：

- **手动**：填写发型、脸型、体型、肤色、标志性配饰
- **AI 提取**：点击 **「提取锚点」**，输入一段角色描述，AI 自动填充

示例角色描述：
```
"30岁冷酷将军，长发，国字脸，高大健壮，小麦肤色，左眼有刀疤"
```

AI 会提取出：
```json
{
  "hair_style": "长发",
  "face_shape": "国字脸",
  "body_type": "高大健壮",
  "skin_tone": "小麦肤色",
  "signature_accessory": "左眼有刀疤"
}
```

#### 步骤 3：生成三视图

点击造型的 **「生成三视图」**，系统会并行调用图片模型生成：
- 正面（front view）
- 侧面（side profile view）
- 背面（back view）

生成后返回三张图的路径，填回造型的 `front/side/back_image_path`。

#### 步骤 4：设为默认造型

在造型列表中点击 **「设为默认」**，则该造型会在分镜生成时自动作为该角色的首选外观。

> ⚠️ **删除限制**：默认造型不可删除，除非该角色只剩这一个造型（防止角色失去外观基准）。

### 3.3 API 参考

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | `/api/v1/characters/:id/outfits` | 列出角色所有造型 |
| POST | `/api/v1/characters/:id/outfits` | 创建造型 |
| GET | `/api/v1/dramas/:id/outfits` | 列出剧本下所有造型 |
| GET | `/api/v1/outfits/:outfitId` | 获取单个造型 |
| PUT | `/api/v1/outfits/:outfitId` | 更新造型 |
| DELETE | `/api/v1/outfits/:outfitId` | 删除造型 |
| PUT | `/api/v1/characters/:id/outfits/:outfitId/default` | 设为默认 |
| POST | `/api/v1/outfits/:outfitId/generate-views` | 提交三视图生成 |
| GET | `/api/v1/outfits/:outfitId/generate-views/status` | 查询三视图状态 |
| POST | `/api/v1/characters/:id/extract-anchors` | AI 提取锚点 |
| GET | `/api/v1/characters/:id/anchors` | 获取角色锚点 |

**创建造型示例**：
```bash
curl -X POST http://localhost:5679/api/v1/characters/1/outfits \
  -H "Content-Type: application/json" \
  -d '{
    "name": "战斗装",
    "description": "铠甲战袍",
    "hairStyle": "束发",
    "faceShape": "国字脸",
    "bodyType": "高大健壮",
    "skinTone": "小麦色",
    "accessory": "腰佩长剑"
  }'
```

## 4. Week 2 — 视频时间线编辑器

### 4.1 概念说明

传统方式是"整集所有分镜一次合并"。V1.0 新增**分段时间线**：可挑选并排序片段，自定义每段起止时间和转场，预览后执行合并。

**关键字段**：`video_merges.segments_json` 存储有序的时间线片段定义。

### 4.2 操作流程

#### 步骤 1：预览可用片段

点击剧本的 **「时间线预览」**，系统返回该集所有可合并的视频片段（含时长和缩略图）。

#### 步骤 2：编排时间线

按目标顺序提供 `segments` 数组：

```json
[
  {
    "videoPath": "data/storage/videos/xxx_1.mp4",
    "startSec": 0,
    "endSec": 5,
    "transition": "fade"
  },
  {
    "videoPath": "data/storage/videos/xxx_2.mp4",
    "startSec": 2,
    "endSec": 8,
    "transition": "cut"
  }
]
```

- `videoPath`：片段视频路径
- `startSec`/`endSec`：截取的起止秒
- `transition`：转场类型（`fade` 淡入淡出 / `cut` 硬切）

#### 步骤 3：执行合并

点击 **「执行时间线合并」**，系统按 segments 顺序用 ffmpeg 拼接并应用转场，返回 `merge_id` 和 `task_id`。

#### 回退逻辑

- **不传 segments**：走原有 `mergeVideoFiles` 逻辑（整集全量合并）
- **传了 segments**：走新的分段时间线逻辑

### 4.3 API 参考

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | `/api/v1/dramas/:id/merge/preview` | 预览可用片段 |
| POST | `/api/v1/dramas/:id/merge/execute` | 执行时间线合并 |
| GET | `/api/v1/video-merges` | 列出合并记录 |
| GET | `/api/v1/video-merges/:merge_id` | 获取合并详情 |

## 5. Week 3-4 — AI Agent 自动工作流

### 5.1 概念说明

V1.0 新增**轻量 DAG 调度器**，把整条短剧生产线编排成有依赖关系的流水线，一键启动自动执行。

### 5.2 三种流水线类型

| 类型 | 步骤 | 适用场景 |
|------|------|---------|
| **`full-production`** | 提取角色 → 提取场景 → 生成角色图 → 生成场景图 → 生成分镜 → 生成视频 → 生成音频 → 合并视频 | 从剧本一步到位成片 |
| **`image-only`** | 提取角色 → 提取场景 → 生成角色图 → 生成场景图 | 只需角色/场景图 |
| **`video-from-existing`** | 生成分镜 → 生成视频 → 生成音频 → 合并视频 | 已有剧本和素材 |

### 5.3 操作流程

#### 步骤 1：确保剧本已有集数和剧情

Agent 依赖 `episodes` 表中的分集数据。

#### 步骤 2：启动流水线

调用 `POST /api/v1/dramas/:id/pipeline/start`，指定 `type`（默认 `full-production`）。

返回：
```json
{
  "pipeline_id": 1,
  "steps": 8,
  "status": "running"
}
```

#### 步骤 3：查看进度

调用状态接口，可查看每一步的 `pending / running / success / failed / skipped` 状态，以及整体 `progress`（0-100%）。

#### 步骤 4：失败处理

- **重试单步**：某步失败后，调用 `retry` 重新执行该步（自动重试上限 3 次）
- **跳过单步**：某步失败但可跳过时，调用 `skip` 强制该步为已跳过状态

#### 步骤 5：暂停 / 恢复

- **暂停**：停止调度新步骤
- **恢复**：继续调度

### 5.4 API 参考

| 方法 | 端点 | 说明 |
|------|------|------|
| POST | `/api/v1/dramas/:id/pipeline/start` | 启动流水线（body: `{type}`） |
| GET | `/api/v1/dramas/:id/pipeline/list` | 列出剧本所有流水线 |
| GET | `/api/v1/dramas/:id/pipeline/:pid/status` | 查询流水线状态 |
| POST | `/api/v1/dramas/:id/pipeline/:pid/pause` | 暂停 |
| POST | `/api/v1/dramas/:id/pipeline/:pid/resume` | 恢复 |
| POST | `/api/v1/dramas/:id/pipeline/:pid/steps/:sid/retry` | 重试单步 |
| POST | `/api/v1/dramas/:id/pipeline/:pid/steps/:sid/skip` | 跳过单步 |

## 6. Week 5 — 剧本专业模板

### 6.1 题材模板（当前为 9 个）

> ⚠️ 原文称「10 大」，实际仓库 `backend-node/src/templates/` 下为 **9 个**：
> 古装、校园、复仇、霸总甜宠、科幻、悬疑、甜宠、穿越、都市。

| ID | 名称 | 说明 |
|----|------|------|
| `romance-boss` | 霸总甜宠 | 霸道总裁与灰姑娘 |
| `sweet-pet` | 甜宠 | 甜蜜宠物式恋爱 |
| `revenge` | 复仇 | 复仇逆袭 |
| `time-travel` | 穿越 | 时空穿越 |
| `suspense` | 悬疑 | 悬疑探案 |
| `ancient-costume` | 古装 | 古装权谋 |
| `urban` | 都市 | 都市情感 |
| `sci-fi` | 科幻 | 科幻幻想 |
| `campus` | 校园 | 校园青春 |
| *(更多可扩展)* | | 通过 YAML 模板文件 |

每个模板内置：
- **角色原型**：男主 / 女主 / 配角定位
- **经典套路**：常用剧情桥段
- **三幕结构**：起承转合
- **节奏曲线**：`rhythm_pattern` 数组

### 6.2 模板生故事

1. `GET /api/v1/templates` 获取模板列表
2. 选定模板，`POST /api/v1/dramas/:id/generate-with-template`，body：
   ```json
   {
     "template_id": "romance-boss",
     "concept": "一个甜品店老板娘和收购她店的总裁的契约恋爱"
   }
   ```
3. AI 基于模板三幕结构 + 用户概念生成完整故事，并自动把 `template_id` 存到剧本

### 6.3 五维质量评分

`GET /api/v1/dramas/:id/quality-score`

对剧本进行五维评分：

| 维度 | 含义 |
|------|------|
| innovation | 创新性 |
| character | 角色饱满度 |
| emotion | 情感真实度 |
| pacing | 节奏张力 |
| theme | 主题深度 |

返回：
```json
{
  "scores": {
    "innovation": 7,
    "character": 8,
    "emotion": 7,
    "pacing": 8,
    "theme": 7
  },
  "comments": { "...": "评语" }
}
```

> 💡 评分结果会缓存到 `dramas.quality_score_json`，再次查询直接返回缓存。

### 6.4 API 参考

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | `/api/v1/templates` | 模板列表 |
| POST | `/api/v1/dramas/:id/generate-with-template` | 模板生故事 |
| GET | `/api/v1/dramas/:id/quality-score` | 五维质量评分 |

## 7. Week 6-7 — TTS 增强 + 唇形同步

### 7.1 多角色音色配置

每个角色可配置多个音色（针对不同情绪/场景）。

**支持的 TTS 引擎**：
- **MiniMax T2A v2**（推荐）：支持 `speed` 语速、`pitch` 音调、`emotion` 情感
- **OpenAI 兼容 TTS**：支持 `speed` 语速

**音色配置字段**：

| 字段 | 说明 | 默认 |
|------|------|------|
| `voice_id` | 音色 ID（MiniMax：如 `female-shaonv`） | 必填 |
| `engine` | `minimax` / `openai` | minimax |
| `model` | 模型名（如 `speech-02-hd`） | 默认 |
| `speed` | 语速 | 1.0 |
| `pitch` | 音调（MiniMax 专属） | 0 |
| `emotion` | 情感（MiniMax 专属） | null |
| `character_id` | 关联角色 | 必填 |

### 7.2 音色试听

配置音色后，点击 **「试听」**，系统用固定文本生成 5 秒预览音频，验证音质和语调。

### 7.3 唇形同步

在视频片段上请求唇形同步，让角色嘴型与配音对齐。

**当前状态**：唇形同步功能为**桩实现**（未正式接入）。`processLipsync` 目前模拟 2 秒后创建空文件，真实唇形同步需在 `lipsyncService.js` 中接入对应服务后启用。
>
> 同理 `cloneVoice`（音色克隆）当前为 **TODO 占位**，返回"未实现"提示，需接入 MiniMax 克隆 API。

### 7.4 API 参考

**音色**：

| 方法 | 端点 | 说明 |
|------|------|------|
| POST | `/api/v1/characters/:id/voice` | 配置角色音色 |
| POST | `/api/v1/characters/:id/voice/clone` | 音色克隆（TODO，未实现） |
| GET | `/api/v1/characters/:id/voices` | 列出角色音色 |
| GET | `/api/v1/voices/:voiceId` | 获取单个音色 |
| PUT | `/api/v1/voices/:voiceId` | 更新音色 |
| DELETE | `/api/v1/voices/:voiceId` | 删除音色 |
| POST | `/api/v1/voices/:id/preview` | 生成 5 秒试听 |

**唇形同步**：

| 方法 | 端点 | 说明 |
|------|------|------|
| POST | `/api/v1/videos/:id/lipsync` | 请求唇形同步（body: `{audio_path, drama_id}`） |
| GET | `/api/v1/videos/:id/lipsyncs` | 列出视频的唇形任务 |
| GET | `/api/v1/lipsyncs/:lid` | 查询唇形任务状态 |

**唇形任务状态**：`pending` → `processing` → `completed` / `failed`

## 8. Week 8 — 运维守护 + 宫格图

### 8.1 系统健康监控

V1.0 后端启动时会自动运行**守护进程**（Guardian），后台周期性自检：

| 检查项 | 周期 | 说明 |
|--------|------|------|
| 临时文件清理 | 每 6 小时 | 清理 storage/temp 下超过 7 天的文件 |

| 磁盘空间 | 每 15 分钟 | 检查剩余空间，判断是否可接受视频任务 |
| 任务超时 | 每 2 分钟 | 检查超时任务并标记 |

`GET /api/v1/system/health` 返回：

```json
{

  "disk": { "freeSpaceGB": 0, "canAcceptVideoTask": true, "lastCheck": null },
  "tempFileCount": { "count": 0, "lastCleaned": null },
  "timedOutTasks": { "count": 0, "lastChecked": null }
}
```

### 8.2 宫格图合成

把多张图片拼成一张网格图（用于视频模型一次生成多镜）：

`POST /api/v1/grids/compose`
```json
{
  "imagePaths": ["path/a.png", "path/b.png", "path/c.png", "path/d.png"],
  "cols": 2,
  "rows": 2
}
```

- 每张图会被 resize 为 **512×512** 统一尺寸
- 输出到 `storage/grids/grid_<timestamp>_<rand>.png`
- 若图片不足 `cols*rows`，会用最后一张补齐

> 💡 **协议无关**：合成的宫格图可提交给任意视频协议（kling 等），不新增分支。

### 8.3 视频切片

把一段长视频切成多个片段：

`POST /api/v1/grids/decompose`
```json
{
  "videoPath": "path/to/video.mp4",
  "segmentCount": 4
}
```

- 使用 ffmpeg 均分切片
- 输出到 `storage/video_segments/<timestamp>/`

| POST | `/api/v1/grids/compose` | 合成宫格图 |

## 10. 常见问题与排查

### Q1: 模板列表为空？
`GET /api/v1/templates` 返回空数组。

**排查**：确认 `backend-node/src/templates/*.yaml` 文件存在，且 `index.js` loader 能正确扫描。若文件缺失，补回 10 个模板 YAML 文件。

### Q2: 音色试听报"未配置 TTS 模型"？
音色记录缺少 `engine` / `voice_id` 字段。

**排查**：确认创建音色时传入了 `engine` 和 `voice_id`，且 AI 配置中已配置对应 TTS 服务商。

### Q3: 唇形同步返回 503？
唇形同步功能尚未正式接入（桩实现）。

**排查**：确认当前版本是否已启用唇形同步能力；当前为占位实现，可直接跳过。

### Q4: Agent 流水线某步一直 pending？
该步的依赖步骤可能未完成。

**排查**：查看状态接口，确认依赖步骤是否为 `success` 或 `skipped`。若有 `failed` 步骤，先 `retry` 或 `skip`。

### Q5: 宫格合成报"images must be a non-empty array"？
`imagePaths` 为空或不是数组。

**排查**：确保请求 body 中 `imagePaths` 是非空数组，且路径存在。

### Q6: 删除默认造型失败（403）？
当前造型是该角色唯一造型，或正处于默认状态。

**排查**：先设另一个造型为默认，或先新增一个造型再删除。

### Q7: 评分接口返回默认 5 分？
AI 评分调用失败（可能未配置文本模型）。

**排查**：确认「AI 配置 → 文本生成」已正确配置且有额度。

### Q8: 首次启动时 `node --test` 报 EPERM？
这是 Windows 沙箱对子进程的限制，不是代码问题。用 `node --test test/*.test.js` 在普通终端运行即可。

## 附：8 周功能回退开关（零影响升级）

V1.0 所有新功能都通过**数据存在性**控制启停，**不配置即走老逻辑**：

| 功能 | 开启条件 | 不开启时的行为 |
|------|---------|---------------|
| 衣橱 | 角色有造型 | 分镜生成用角色默认形象 |
| 时间线 | 传 `segments` | 走原整集全量合并 |
| Agent | 手动调用 pipeline API | 不自动触发，无副作用 |
| 模板 | 使用 generate-with-template | 不影响原手动编剧本 |
| 音色 | 配置 voice | TTS 用系统默认音色 |
| 唇形 | 请求 lipsync | 不请求则不影响视频 |
| 守护 | 后端启动自动运行 | 无需开关，静默守护 |
| 宫格 | 调用 grids API | 不影响原单图流程 |
