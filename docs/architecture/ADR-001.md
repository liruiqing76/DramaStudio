# ADR-001: DramaStudio 架构评估与改造路线

## 状态
Accepted (2026-09-03)

## 背景
项目当前处于 MVP→Pre-prod 过渡期：功能链闭环可用，但技术债严重（3 万行纯 JS、单文件 4000+ 行、零测试、零鉴权、零成本追踪）。五方联合评估确认必须分阶段偿还。

## 决策
1. **架构边界**：按 DDD 领域拆分，单 service ≤ 500 行
2. **横切关注点**：middleware 层（logger/cost/auth/errorHandler）
3. **TS 策略**：JSDoc + `checkJs` 渐进过渡，新模块强制 TS
4. **VendorAdapter**：三套接口（Image/Video/TTS），加厂商 = 加一个文件
5. **Phase 划分**：Phase 1（止血计费）→ Phase 2（架构扩展）→ Phase 3（内容质量）

## 已落地（2026-09-03）
- `src/middleware/costTracker.js` — 成本追踪中间件（含 PRICE_TABLE）
- `src/middleware/logger.js` — 结构化日志 + requestId 注入
- `src/middleware/errorHandler.js` — ApiError 类 + 统一错误响应
- `src/middleware/auth.js` — X-Client-Token 鉴权（默认关闭，配置开启）
- `migrations/23_add_cost_records.sql` — 成本记录表
- 更新 `src/app.js` — 接入上述中间件

## 待办
- Phase 1.3: `src/adapters/media/ffmpeg.js` — 媒体抽象层（BGM/cross-fade/字幕描边）
- Phase 1.4: 前端费用展示组件
- Phase 1.5: 集成测试（Sprint 2）

## 影响
- 用户跑一集前可看到预估费用
- 出问题能通过 requestId 5 分钟内定位
- 成片质量提升（BGM + 转场）
